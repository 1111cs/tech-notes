# harness和learn-claude-code项目

## llm,agent,harness

1、LLM 只是大脑，

2、而 Agent 是“大脑 + 自主决策闭环”。 

3、Harness 原意是“马具”或“挽具”，在这里指“驾驭 AI 的基础设施”。

如果没有 Harness，LLM 只是一个在真空中思考的“大脑”

如果把 Agent（模型）比作一匹千里马（或赛车手），Harness 就是套在它身上的马具（或赛车本身）。它是为了让模型在特定领域（如编程、农业、酒店管理）能够实际工作而编写的所有外围代码和系统。

Harness 包含了模型工作所需的一切：

- **Tools（工具）：** 给模型一双手。比如文件读写、Shell 执行、API 调用。
- **Knowledge（知识）：** 给模型领域专长。比如产品文档、API 规范。
- **Observation（观察）：** 给模型眼睛。比如让它看到 `git diff` 的结果、错误日志。
- **Permissions（权限）：** 给模型边界。比如沙箱隔离，防止它删库跑路。

## Claude Code的“放权“

### 核心思想

 Claude Code 之所以强大，不是因为它用的模型比别人聪明，而是因为它构建的“工作环境”（Harness）最懂如何“放权”和“赋能”。 

### 最好的 Harness 是“隐形”的（做减法）

 Claude Code 的成功在于它**“没做”**什么。

- **错误做法**：很多开发者试图用代码写死工作流（比如：第一步必须干嘛，第二步必须干嘛），或者用复杂的决策树去限制模型。这相当于给赛车手（模型）绑上了绳子，限制了他的发挥。
- **Claude Code 的做法**：它**“让开了”**。它不教模型怎么思考，而是提供一套完美的工具和环境，然后信任模型去决策。
- **结论**：Harness 的职责是**提供能力**，而不是**限制思维**。

### Claude Code 的本质公式

Claude Code = 模型 (大脑) + 12种 Harness 机制 (身体/环境)

重点在于： 这些全是工程代码（Harness），而不是模型训练。这证明了95% 的工作量在于构建这个环境，而非模型本身。

| 原文术语        | 翻译与解释 | 作用                                             |
| --------------- | ---------- | ------------------------------------------------ |
| Agent Loop      | 核心循环   | 模型不断“思考-行动-观察”的发动机。               |
| Tools           | 工具箱     | Bash、读写文件等，给模型动手能力。               |
| 按需 Skill 加载 | 技能包     | 只有需要时才给模型看文档，防止信息过载。         |

| 子 Agent 派生   | 分身/外包  | 遇到复杂任务，主模型可以叫“小弟”去干，互不干扰。 |
| Worktree 隔离   | 沙箱环境   | 在独立的文件夹里干活，防止把主项目搞挂了。       |
| 权限治理        | 安全锁     | 规定哪些命令能跑，哪些需要用户确认。             |
