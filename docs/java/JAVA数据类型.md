## JAVA数据类型

Java 里有两套数值体系：**基本类型**存“原始值”，**包装类**把它们包装成对象。日常写代码时，基本类型更轻更快，包装类更适合集合、泛型、数据库字段和需要 `null` 的场景。

### **8 种基本类型和对应包装类**

| 基本类型  |   包装类    |   默认值   |
| :-------: | :---------: | :--------: |
|  `byte`   |   `Byte`    |    `0`     |
|  `short`  |   `Short`   |    `0`     |
|   `int`   |  `Integer`  |    `0`     |
|  `long`   |   `Long`    |    `0L`    |
|  `float`  |   `Float`   |   `0.0f`   |
| `double`  |  `Double`   |   `0.0d`   |
|  `char`   | `Character` | `'\u0000'` |
| `boolean` |  `Boolean`  |  `false`   |

### **核心区别**

- **本质不同**：基本类型不是对象；包装类是对象，继承 `Object`。
- **默认值不同**：基本类型有固定默认值；包装类默认值是 `null`。
- **能否为 null**：基本类型不能为 `null`；包装类可以，所以适合表示“可能没有值”的场景，比如数据库字段、接口参数。
- **存储和性能**：基本类型直接存值，开销小；包装类是堆上的对象，有额外开销。
- **集合和泛型**：`List`、`Map` 等集合只能存对象，不能写 `List`，必须用 `List`。
- **比较方式**：基本类型用 `==` 比较值；包装类比较值要用 `equals()`，不要用 `==`。

### **自动装箱 / 自动拆箱**

这是编译器提供的语法糖，不是 JVM 运行时魔法。

```
Integer a = 10;   // 自动装箱，底层是 Integer.valueOf(10)
int b = a;        // 自动拆箱，底层是 a.intValue()
```

### **包装类缓存机制**

`Integer.valueOf()` 会复用 `-128 ~ 127` 范围内的对象，所以：

```
Integer a = 127;
Integer b = 127;
System.out.println(a == b); // true，缓存复用同一对象

Integer c = 128;
Integer d = 128;
System.out.println(c == d); // false，超出缓存范围，是新对象
```

`Byte`、`Short`、`Long`、`Character` 也有类似缓存；`Float`、`Double` 没有缓存。

### **两个高频坑**

1. **包装类比较用 `equals()`**
   `==` 比较的是对象引用，受缓存影响，结果不可靠。
2. **自动拆箱可能 NPE**
   如果包装类是 `null`，拆箱时会抛 `NullPointerException`。

编辑







```
Integer x = null;
int y = x; // NullPointerException
```

### **开发怎么选**

- 局部变量、循环计数、纯数值计算：优先用 **基本类型**。
- 集合、泛型、数据库实体字段、RPC 参数、可能为空的值：用 **包装类**。
- 包装类之间比较值：统一用 **`equals()`**。
