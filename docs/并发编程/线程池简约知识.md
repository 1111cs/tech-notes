### 1、定义线程的方式

1）直接new Thread,在括号里面直接写lambda表达式；

2）先显示定义一个runnable对象，再将其作为Thread类的 new() 的参数。

### 2、创建线程池

**我们要知道线程池是可以通过new ThreadPoolExecutor（）来实现的**，然后参数可以传一些注入核心线程数，maximumpoolsize(允许创建的最大工作线程数)等等。

 **Executors.newFixedThreadPool(4)的方式也可以创建一个线程**，它在底层依然是调用了new ThreadPoolExecutor(...)。好处就是：它帮你把 corePoolSize、maximumPoolSize、BlockingQueue 等参数全部填好了（比如 newFixedThreadPool 就把核心线程数和最大线程数都设为了 4）。

### 3、创建完线程池之后的任务提交

1）可以使用execute()：提交不需要返回结果的任务，任务的定义使用runnable对象；

```
executorService.execute(() -> {
    System.out.println("开始统计 Excel 行数");
    // 执行统计逻辑
});
```

2)也可以使用sumbit(),提交任务并获取Future，这里可以是一个Callable接口；

**返回值类型是Future.我们可以通过 future.get()去拿结果；如果任务报错了，调用 get() 时会把异常抛给你，而不是悄无声息地消失。甚至可以通过 future.cancel() 尝试把任务取消掉。**

```java
Future<Integer> future = executorService.submit(() -> {
    // 模拟统计结果
    return 1000;
});
```

3）也可以使用 CompletableFuture.supplyAsync()方法来调用，**它第一个参数传入的**是一个Supplier&lt;T&gt;对象，相对的，如果使用的是

```java
public static CompletableFuture<Void> runAsync(
    Runnable runnable,
    Executor executor
)
```

它传入的就是一个Runnable对象。**future就是CompletableFuture<>类型，至于我们要返回具体什么类型，就在泛型里面写，譬如String。**

**另外它还得有第二个参数。即一个线程池作为执行器。**

CompletableFuture 是 Java 8 引入的异步编程工具,它实现了 Future 和 CompletionStage 接口。CompletableFuture 是 Java 8 以后更推荐的“完全体”，而 Future 是它的“基础版”。。**你可以把它当成一个普通的 Future 来用，但因为它实现了 CompletableFuture 自己的接口，**所以它比普通 Future 多了一堆“花里胡哨”的超强技能。单独使用 Future 的痛点是：太被动，只能干等。而 CompletableFuture 的核心是 “链式回调”，也就是流水线思维。

```java
CompletableFuture<String> future =
    CompletableFuture.supplyAsync(
        () -> {
            return "查询成功";
        },
        priceExecutor
    );
```

### 5、函数式接口

函数式接口（Functional Interface）是一个有且仅有一个抽象方法的接口。Runnable 就是最典型的函数式接口。

Lambda 表达式 { System.out.println("执行任务"); } 里的代码，就是在给 Runnable 接口里唯一的抽象方法 run() 提供具体实现。

我们认识了4个函数式接口，
1）Runnable，它的抽象方法是run()；无参数、无返回值
2）Supplier&lt;T&gt;，它的抽象方法是get()，有参数、无返回值
3）Consumer&lt;T&gt;，它的抽象方法是accept(T)
4）Function&lt;T,R&gt;，它的抽象方法是apply(T)

List<CompletableFuture<List<SupplierPriceVO>>> futures =

我们先逐步来解析：

#### stream的作用和使用

```java
List<CompletableFuture<List<SupplierPriceVO>>> futures = new ArrayList<>();
for (SupplierMapping m : suppliers) {
    // 必须手动创建集合
    // 必须手动把每一个元素加进去
    futures.add(CompletableFuture.supplyAsync(() -> invokeAdapter(m, req, customerDictMap), priceExecutor));
}
```

1、右边可得：这本质是一个集合。new ArralyList<>();

左边可得：我们获得了一个future的集合future是一个并发线程的结果。这里因为要收集多个线程的结果，所以我们使用了一个集合来接收。

2、futures.add(CompletableFuture.supplyAsync(() -> invokeAdapter(m, req, customerDictMap), priceExecutor));
这里就是使用了CompletableFuture.supplyAsync来要执行的任务。

然后我把结果加入到上面的集合futures中。

**如果加了stream的话，就是**

```java
List<CompletableFuture<List<SupplierPriceVO>>> futures =
    suppliers.stream()
        .map(m -> CompletableFuture.supplyAsync(
            () -> invokeAdapter(m, req, customerDictMap),
            priceExecutor
        ))
        .collect(Collectors.toList());
```

1. 开启流水线：`suppliers.stream()`
2. 规定转换规则（`map`）：把每个对象变成一个异步任务。
3. 一键装箱：`.collect(Collectors.toList())`

这里的m指的就是分销商集合，我们要对统计他异步执行invokeAdapter得到的结果，也就是最终的stream的结合要变成CompleableFuture集合，所以才使用map。

map() 虽然只是映射操作，但映射过程中调用的 supplyAsync() 是会立即提交任务的。

执行过程是：

1. collect() 触发 Stream 流水线。
2. map() 开始逐个处理分销商。
3. 每处理一个分销商，就调用一次 supplyAsync()。
4. supplyAsync() 将任务提交给线程池。
5. map() 返回对应的 CompletableFuture。
6. collect() 将这些 CompletableFuture 收集到 List 中。

所以，Stream 的惰性不意味着 map() 里面的方法不会执行，而是要等到终止操作触发流水线之后才执行。
